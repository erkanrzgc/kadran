# TOTP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A stolen admin SSH key alone can no longer manage a Kadran server once TOTP is enabled; `kadran login` exchanges a TOTP code for an 8-hour session token bound to the key.

**Architecture:** A pure `internal/totp` package (RFC 6238, recovery codes, HMAC session tokens) and an SQLite table hold the state. kadrand enforces the token in the existing K-131 authorization interceptor for admin callers, and five new RPCs manage login and enrollment. The CLI caches tokens per target and attaches them as gRPC metadata. Root on the server has a local reset path.

**Tech Stack:** Go standard library only (`crypto/hmac`, `crypto/sha1`, `crypto/sha256`, `crypto/rand`, `encoding/base32`), SQLite migrations, protobuf/gRPC via `buf generate`.

**Spec:** `docs/specs/2026-10-24-totp-design.md`

## Global Constraints

- `go.mod` and `go.sum` unchanged; no new dependency.
- The executor (`cmd/kadran-exec`, `internal/exec`) is untouched; `bash scripts/check-exec-surface.sh` passes.
- Protocol stays 3 (`version.Protocol`); only new RPCs and one `optional` field.
- Every user-visible string (CLI, gRPC errors, slog, alarm detail) is English; `go test ./cmd/kadran -run English` passes (K-141, K-153).
- No secret, code, recovery code or token ever goes into an audit record, log line or alarm detail.
- Algorithm: HMAC-SHA1, 30 s step, 6 digits, ±1 step.
- Session lifetime 8 h. Pending enrollment expires after 10 min.
- Lockout: after 5 consecutive failures, 1 min, doubling per further failure, at most 1 h.
- Recovery: 10 codes, 10 base32 characters each, stored as SHA-256, single use.
- Commit messages: one line `update <few English words>`, no body, no Co-Authored-By.
- Before each commit: `gofmt -l ./cmd ./internal` empty, `go vet ./...`, `go test -count=1 ./...`, `golangci-lint run ./...`. After proto changes `buf lint` and `buf generate` (generated `*.pb.go` are gitignored).
- Go needs `export PATH="/c/Users/erkanrzgc/AppData/Local/Programs/go/bin:/c/Users/erkanrzgc/go/bin:/c/msys64/mingw64/bin:$PATH"` in every shell.

## Review Focus

1. **Phone or server clock off by more than 30 s.** The code is rejected; the error must say to check the clock, not only "wrong code". Pinned in Task 4 (`TestLoginOutsideWindowMentionsClock`).
2. **The same code used twice at once** (two terminals). Exactly one login wins. Pinned in Task 2 (`TestAcceptTOTPStepIsOneShot`) and Task 4 (`TestLoginRejectsReplayedCode`).
3. **A token cached before re-enrollment.** The server rejects it with "session expired, run kadran login", not a generic error. Pinned in Task 4 (`TestOldGenerationTokenIsRejected`).
4. **CI deploy keys after enabling TOTP.** `Deploy` still works without a token. Pinned in Task 4 (`TestDeployRoleIsExemptFromSession`).
5. **An enrollment abandoned halfway.** TOTP stays off, and a confirm after 10 min is refused. Pinned in Task 4 (`TestPendingEnrollmentExpires`).

### Task 1: `internal/totp` package

**Files:**
- Create: `internal/totp/totp.go`, `internal/totp/recovery.go`, `internal/totp/token.go`, `internal/totp/lock.go`
- Test: `internal/totp/totp_test.go`, `internal/totp/recovery_test.go`, `internal/totp/token_test.go`, `internal/totp/lock_test.go`

**Interfaces:**
- Produces:
  - `const Period = 30 * time.Second; const Digits = 6; const SecretSize = 20`
  - `func NewSecret() ([]byte, error)`: `SecretSize` random bytes.
  - `func EncodeSecret(secret []byte) string`: base32 standard alphabet, no padding.
  - `func OTPAuthURI(secret []byte, issuer, account string) string` → `otpauth://totp/<issuer>:<account>?secret=…&issuer=…&algorithm=SHA1&digits=6&period=30` (escaped).
  - `func StepAt(t time.Time) int64` = `t.Unix() / 30`.
  - `func codeAt(secret []byte, step int64, digits int) string` (RFC 4226 dynamic truncation).
  - `func Verify(secret []byte, code string, now time.Time, lastStep int64) (step int64, ok bool)`: tries `StepAt(now)-1 … +1`, accepts only `step > lastStep`, constant-time compare, rejects anything that is not exactly 6 ASCII digits.
  - `func InWindow(secret []byte, code string, now time.Time, span int64) bool`: whether the code matches any step within ±span (used only to tell "clock" from "wrong").
  - `const RecoveryCount = 10`; `func NewRecoveryCodes() ([]string, error)` formats as `XXXXX-XXXXX`; `func HashRecovery(code string) [32]byte` normalizes (upper-case, drop `-` and spaces) before SHA-256.
  - `type Claims struct { Fingerprint string; Expires time.Time; Generation int64 }`
  - `const TokenLifetime = 8 * time.Hour`; `const TokenKeySize = 32`
  - `func SignToken(key []byte, c Claims) string` → `v1.<b64url(json)>.<b64url(hmac-sha256)>`, JSON keys `fp`, `exp` (unix seconds), `gen`.
  - `func ParseToken(key []byte, token string) (Claims, error)`; errors `ErrMalformedToken`, `ErrBadSignature`.
  - `const LockAfter = 5; const LockBase = time.Minute; const LockMax = time.Hour`; `func LockDuration(failures int) time.Duration` (0 below `LockAfter`).

  - `LockedLogins(ctx, now time.Time) ([]LoginFailure, error)`: rows with `locked_until > now`.

**Interfaces:**
- Consumes: Task 1 package, Task 2 store methods, Task 3 messages.
- Produces:
  - `type SessionGate interface { CheckSession(ctx context.Context, id connproto.Identity, method string) error }`; `AuthzUnaryInterceptor(gate SessionGate)`, `AuthzStreamInterceptor(gate SessionGate)`; `NewGRPCServer` passes `service`.
  - `func (s *Server) CheckSession(ctx, id, method) error`: nil for `RoleDeploy`, for methods `Ping` and `Login`, and when TOTP is not enabled; otherwise reads metadata key `kadran-session` and returns `codes.Unauthenticated` with one of these exact messages:
    - no token: `TOTP is on for this server: sign in with "kadran login" (upgrade kadran if it has no login command)`
    - expired, or old generation: `session expired: sign in again with "kadran login"`
    - bad signature, malformed, or another key's fingerprint: `invalid session token: sign in again with "kadran login"`
  - `ServerOptions.Alarms` of type `interface{ Raise(ctx context.Context, a store.Alarm); Clear(ctx context.Context, id string) }`, which is `*alarm.Manager`'s method set (`alarm.go:98,132`). Nil is allowed, and in that case no alarm is raised (tests).
  - Handlers `Login`, `BeginTotpEnrollment`, `ConfirmTotpEnrollment`, `DisableTotp`, `GetTotpStatus`, with these rules:
    - **Empty fingerprint:** `FailedPrecondition "signing in needs an SSH key identity"`.
    - **Login while TOTP is off:** `FailedPrecondition "TOTP is not enabled on this server"`.
    - **Locked fingerprint:** `ResourceExhausted "too many failed codes for this key: try again in <d>"` (rounded to minutes), and the code is NOT checked.
    - **Wrong code:** `PermissionDenied`. The message is `"code rejected: check that your phone's clock is correct"` when `totp.InWindow(..., 4)` matches, otherwise `"code rejected"`.
    - **Replay:** `PermissionDenied "code already used: wait for the next one"`.
    - **Every failure:** `RecordLoginFailure` and an audit record `auth.login` with outcome failure and detail = the reason word (`wrong_code`, `clock`, `replay`, `locked`, `recovery_wrong`).
    - **The failure that locks the key:** `Alarms.Raise` with `{ID: "login_lockout:"+fp, Kind: KindLoginLockout, Target: fp, Severity: SeverityWarning, Detail: "N failed codes for key <fp>, locked until <RFC3339>"}`.
    - **Success:** `ClearLoginFailures`, `Alarms.Clear("login_lockout:"+fp)`, a token with `TokenLifetime`, and audit `auth.login` success.
    - **Recovery code:** audit detail `recovery`, plus a warning alarm `login_recovery:`+fp, `"recovery code used, <n> left"`.
    - **`BeginTotpEnrollment`:** the issuer is `Kadran` and the account is the hostname. Pending expires 10 min after `PendingCreatedAt`. Audit `totp.enroll`.
    - **`ConfirmTotpEnrollment`:**
      - verifies against the PENDING secret, then calls `ConfirmTOTP` with a fresh token key and 10 hashed recovery codes;
      - returns the codes and a token;
      - writes audit `totp.confirm`;
      - when the pending enrollment has expired, returns `FailedPrecondition "enrollment expired: run kadran totp enable again"`.
    - **`DisableTotp`:** the session is already checked by the gate, and it also needs a fresh valid code. Audit `totp.disable`.
  - `Ping`: `TotpRequired: proto.Bool(state.Enabled())`. A store read error leaves it unset, so Ping never fails because of it.
